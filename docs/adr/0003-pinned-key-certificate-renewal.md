# Pin the server key after authenticated pairing

A certificate fingerprint from the QR authenticates first contact. Over that pinned HTTPS channel the client learns the SHA-256 fingerprint of the server TLS public key (P-256 uncompressed X9.63 bytes), together with current HTTPS origins. Once remembered, the key pin is mandatory: a matching old certificate cannot override a different remembered key. Hostname, validity and TLS handshake checks remain enforced. The TLS key is separate from the broker identity used for approval signatures.

The daemon preserves its private key, renews its 90-day certificate after 60 days or when discovered addresses need new SANs, and checks interfaces once a minute. A single atomic TLS snapshot supplies current certificate and addresses to local pairing and remote health discovery; PEM/DER files remain compatibility exports. Existing installations initially retain their certificate to let updated clients learn the key. Certificate-only clients must upgrade before renewal; an offline client that never learned the key must scan a fresh QR after renewal. Replacing the private key is an explicit identity migration, not routine renewal.

Clients race read-only authenticated health probes, learn addresses only from the verified server, and send each POST once. An uncertain submission is never retried automatically. At least one remembered address must remain reachable; simultaneous loss of every known address needs stable DNS/VPN addressing or a new QR. Network address discovery does not establish a VPN or change its access controls.

Both iOS targets enable local-network access and declare a scoped ATS exception for `100.64.0.0/10`, used by mesh VPNs. On iOS 17+, local-network access alone does not permit pinned self-signed TLS on that range: ATS rejects system trust before the authentication delegate runs. The exception allows custom trust evaluation with TLS 1.2 or later; it does not enable HTTP in xlatch, and no global arbitrary-load exception is declared. App Store review notes must explain the scoped exception for user-paired self-hosted servers. The shared client also rejects HTTP, credential-bearing origins and redirects independently, then authenticates self-signed HTTPS servers with the key pin established during pairing. Live URLSession tests verify a reachable pinned server, fallback from an unavailable origin, and rejection of the wrong certificate pin. The signed app and share extension must have identical transport dictionaries.
