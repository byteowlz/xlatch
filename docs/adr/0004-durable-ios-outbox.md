# Durable iOS Outbox

Shares, App Intents and in-app submissions persist an immutable input, device public key, original server pin and exact capability revision before attempting delivery. The App Group SQLite store coordinates app and extension writers with transactions and expiring delivery leases. Private signing keys remain in Keychain. The directory uses iOS file protection and is excluded from backups; payloads are removed after server acceptance, cancellation or expiry. Unsent content is limited to 50 items / 64 MB and expires after seven days; cleanup runs when the store is accessed.

A lost response is ambiguous: the server may already have accepted work. Retrying therefore retains the invocation idempotency key and exact payload, while signing a fresh request envelope. The server's persisted job/key deduplication is part of this guarantee; deleting that history without retaining deduplication records would invalidate safe retries. The client rechecks pairing, local enablement and granted revision before invoking. It never substitutes a replacement revision or session. Certificate trust failures and permission changes pause work. Stopping retries or deleting a local item cannot undo a request already in flight or a server job.

Background URLSession uploads cannot safely hold a pre-signed request indefinitely because its timestamp expires. Retry opportunities instead run the ordinary pinned, signed client on foreground activation, network changes while running, and best-effort BGProcessing tasks. iOS controls background scheduling; delivery is not guaranteed immediately on reconnection. A queued App Intent returns an `outbox:` receipt instead of claiming a server job exists. The Outbox retains the resulting job ID after acceptance.
